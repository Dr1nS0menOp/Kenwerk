## Findings along the way

- **The application role is the hard part of a managed database.** Kenwerk grants tables to it after each migration (`db.GrantApp`), but the role must exist, and only Compose's init script and the LXC script make it. Without the new step every cloud install would have needed a `psql` session by hand.
- **PostgreSQL 16 makes the owner a member of each role it creates**, so "grant the owner to the application role" fails as circular; a role someone else made that holds the owner's rights is refused by PostgreSQL itself when the owner tries to set its password. The test accepts either refusal.
- **The `postgres` image trusts connections from 127.0.0.1 without a password**, which made the first version of the password test pass for the wrong reason; it now connects through the container's name.
- **pgx 5.12 reads `sslrootcert=system`** as the system's roots and libpq 16 does too, so one address works for the server and for `pg_dump` against Azure.
- **cfn-lint refuses RDS `EngineVersion` 16 and 16.1 to 16.8** for new databases; the template starts at 16.13.
- **Bicep's build is not byte-stable**: the order of `dependsOn` lists, and the `templateHash` that follows it, changed between the PC and the build VM with the same binary. The check compares the templates with those lists sorted and the hash left out.
- **Terraform after 1.5.7 is BUSL-1.1**, so CI pins 1.5.7 next to OpenTofu.
- **Container Apps always overlaps revisions**, so the embedded queue's folder is a temporary volume per replica there (spec 099, D6). ECS and Kubernetes can stop the old task first.
- **Cloud Run** was set aside: no step before the server, and no volume that suits the queue without Filestore.
- **A "Launch stack" link needs an S3 bucket**; pointing at a bucket the project does not own would let someone else serve a template under our README. No AWS button until the product owner owns one.

## Not proven

No template has been deployed on a cloud. Things only a real run shows:

- Azure: SMB mount options with uid 65532, the storage account's network rule with Container Apps' mounts, the backup service's `chown` on SMB, nested mount of the queue folder over the data share, the Deploy button's form with `newGuid()` defaults.
- AWS: the CloudFront VPC origin to an internal load balancer, EFS access points with the backup service, the first step's task-local volumes.
- Google Cloud: the managed certificate and FrontendConfig through `extraObjects`, Cloud SQL's built-in user creating the role, the Cloud Shell tutorial path.
- Every target: that the published images exist. No release tag exists yet.
