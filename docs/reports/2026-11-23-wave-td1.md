Builder report. Documentation only: no code, test or configuration changed.

## What was done

- `docs/testing.md`, written for a reader new to the repository. Every row of its table of checks was read in `.github/workflows/ci.yml`, `release.yml`, the `Makefile`, `scripts/` and `web/package.json`.

## How the numbers were measured

On `main` `e5e8323`, 2026-11-23. Most were counted with `git ls-files`, `git grep` and `grep`, as `testing.md` gives them. Four were run:

- the permission matrix, with `go test ./internal/permissions -run '^TestMatrixEvaluate$' -v` in a `golang:1.26` container: 37,813,800 cases. This is the product of the case tables, worked out by hand first;
- `npx vitest run` in a `node:22` container with `KENWERK_REPO` set to the checkout: 58 files and 956 tests. Without `KENWERK_REPO`, two files fail because they read the Go side's test tables from the repository;
- `npx playwright test --list`: 699 tests in 43 files. A CI run of the same commit reported 687 passed, 10 skipped and 2 failed, which is also 699;
- the ten skipped tests are `collab.spec.ts`, which runs only with `E2E_COLLAB=1`.

## Found, not changed

- **The nightly job has not passed since 12 November 2026.** All 11 nightly runs since failed, mostly in or during the full mutation check, and on 23 November the hosted runner ran out of disk there. Stryker, added in wave QG1, has not completed in CI. `testing.md` says so with the date. `docs/beta-criteria.md` (C2, U4) counts these as met "as a gate".
- **`main` at `e5e8323` is red** in the e2e job: two tests of `people.spec.ts` (anonymising, and a reset link) timed out.
- **The DCO job never checks what lands**, because it runs on pull requests only and waves land by push.
- **Four fuzz targets are not fuzzed at night**, only run on their seeds: `FuzzEvaluationIsTotalAndBounded`, `FuzzImportArchive`, `FuzzRewriteLeavesNoDraftID` and `FuzzValidateNeverAcceptsAWorkflowWithoutAWayToApproval`.
- **Stale counts elsewhere.** Blueprint 05, chapter 11 gives 11,929,005 matrix cases from older tables. The threat model and SEC-203 give 102,960. `limits.md` calls the nightly restore drill "the weekly restore test". The `nightly` job comment says nine frontend mutations, where there are 39.
- **`CLAUDE.md` and practice differ on mutations at landing.** `CLAUDE.md` says landing on `main` always runs every mutation. Recent reports (MC2, MC3, QG2, SR3) ran the targeted check and left the full run to CI. `testing.md` describes the practice.
- **`CHANGELOG.md`:** the SR3 entry's "Upgrade impact" line runs into a heading `### Fixed: four things the product owner saw on 2026-11-22 (wave FX7)` that has no lines under it.
