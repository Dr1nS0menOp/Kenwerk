# Wave MC2: scopes per route, spaces on tokens, tokens for an assistant

Builder report for the first build wave of spec 096 (access through the Model Context Protocol). It covers what was looked at, changed and proven.

## What was looked at

- Spec 096 in full, the token code (`internal/identity/tokens.go`), the router and its rules (`internal/httpapi/router.go`, `server.go`), the access rule (`internal/permissions/evaluate.go`, `service.go`), the perm_* functions in the migrations, the audit event (`internal/audit/audit.go`), the limiter, the token screen in Your account, and the 614 lines of `docs/api/routes.txt`.
- Every route was given a scope by a first sorting on method, path and rule, then by hand where the first sorting could not know: sharing, sites, guests, group members, restrictions, access requests (`content:share`); a space's access, roles, automation, webhooks, templates, workflows, releases, archive, delete and trash (`spaces:manage`); deleting and archiving (`content:delete`); one's own notifications and preferences (`account:*`); the directory, people and groups (`people:read`); class N of the spec (`none`).
- Of the 134 calls of perm_* functions in the code, 98 call one of the seven functions that list what a person reaches. About 70 had their SQL straight in the call; the rest are fragments shared between queries (search, the feed, the tree, notifications, references of a page, files), which were done by hand with the placeholder each query needs.

## What changed

- **Scopes per route.** `internal/httpapi/scopes.go` holds `routeScopes`, one line per route. The router gives each route its scope at registration and refuses to start when a route that a token can reach has none, or when `scope:none` sits on a route a token could reach. `routes.txt` prints `scope:...`, `openapi.json` has `x-scope`. `scopeFor` and `exportRoutes` are gone.
- **Old words as bundles.** `internal/identity/scopes.go`: a stored `read`, `write`, `export` or `admin` holds exactly what it reached before. A word sent when making a token now means its new bundle: `write` is `content:write content:delete account:write`.
- **Spaces on tokens.** `api_tokens.space_ids` (at most 50, checked in the table as well) and `assistant`. A space limit must name spaces the person sees, and rules out every `admin:` scope. Without `spaces` a token reaches every space (the product owner's decision of 2026-11-22).
- **The limit in Evaluate and SQL.** The HTTP layer puts the limit in the request's context; `LoadUser` gives it to the credential's own person, after the memo and cache; `Evaluate` checks `space_limit` first, as a check of visibility. The seven list functions have a new signature with `allowed uuid[]`, and every call passes `permissions.CredentialSpaces(ctx)`. Calls about Administration and about one space that `RequireSpace` checked first pass `NULL`, each with a comment saying why.
- **Routes outside every space.** Making a space or a personal space, the members of a group, and changing a template refuse a limited token with `403 token_spaces`.
- **`via`.** `audit.Event` ends with `via`; `identity.RequestMeta` carries it, `metaFrom` fills it from the principal, `Caller.Event` and the identity events write it. `token.used` names the token too. An old `write` token reaching `content:share` or `spaces:manage` sets `via.old_write`.
- **Limits.** `internal/httpapi/credentials.go`: 1,200 a minute for all tokens of one person, 120 changes and 20 deletes, shares or access changes for a token for an assistant, `429` with `Retry-After: 60`, `token.rate_limited` once a minute per token.
- **The token screen.** Scopes in plain words, every space or chosen spaces (radio, chips, a list to add one, at most 50), For an assistant; the table shows spaces and an Assistant lozenge.
- **Docs.** `docs/api/README.md` (scopes, old words, spaces, assistants, limits, and the stability promise from 1.0 on), spec 096 "Built in wave MC2" with decisions D17 to D20, blueprint status lines of PLT-037, PLT-047 and PLT-048, the changelog.

## How the tests prove it

- `TestATokenReachesOnlyWhatItsScopesAndSpacesAllow` (internal/app) walks every route of the real table with real HTTP: a token holding exactly the route's scope passes the token check; one with every other scope does not; a token limited to a space never reaches an `admin:` route or a route outside every space (`token_spaces`); a token of each old word reaches exactly what its bundle says; a session-only route refuses all of them. About 4,000 requests, 14 s.
- `TestTheWriteScopeNoLongerCoversWhatReachesOutside`, `TestEveryRouteBelowAdministrationNeedsAnAdministrationScope`, `TestTheScopeTableHoldsOnlyRealRoutes` hold the table itself.
- `TestANewTokenReachesEverySpaceUnlessItIsLimited`: the default, `404` outside the limit for a page, a space, its tree, comments and files, a change outside refused, lists and search narrowed, making a space refused.
- `TestATokenIsLimitedOnlyToSpacesItsPersonSeesAndNeverToAdministration`, `TestTheWordWriteOfANewTokenNoLongerShares`, `TestEveryEventOfATokenNamesTheToken` (and that the chain verifies), `TestATokenWithEveryScopeIsStillOnlyItsPerson`, `TestATokenPastItsLimitIsToldWhenToTryAgain`.
- The matrix (`internal/permissions`): the literal rule gains the credential's limit; `Evaluate` is compared with it for a session, a limit holding the space and a limit without it; the SQL half compares `perm_visible_pages`, `perm_listed_pages` and `perm_editable_pages` with and without a limit to every other space, and `Evaluate` on loaded facts with the same limit. `TestTheSmallerListsKeepToTheLimit` covers `perm_spaces`, `perm_visible_comments` and the old signature. `TestEveryListPassesTheSpacesOfTheCredential` refuses a call of an old signature anywhere in the code. `TestTheLimitOfACredentialIsItsOwnPersonsAlone` holds the context rule.
- `internal/httpapi`: a route without a scope does not start, `scope:none` only where no token reaches, and each limit at its count and key.
- 26 new or rewritten mutation lines in `scripts/mutation-check.sh` under "Spec 096, wave MC2"; three lines that named `scopeFor` and `exportRoutes` were rewritten or dropped with the code.
- e2e: `a token for an assistant reaches every space unless spaces are chosen` (people.spec.ts), and the design pictures `tokens` and the new `tokens-chosen-spaces`.

The race tests of the third run: `internal/permissions` reached the 45-minute limit in its matrix (known on the loaded VM; it passes on GitHub CI; the matrix itself passed locally, 37.8 million cases and 126,936 pages, before the move to the VM); `TestAWholeSpaceReleaseFitsItsBudget` measured 8 pages a second under load (known to fail on a loaded VM, see the report of wave RV11); and `TestAnOldPageIsFoundBehindAWholeWindowOfNewerPages` found nothing in two race runs, while it passes without `-race` on this branch (the targeted run of `internal/app` above). Run on its own with `-race` on the idle VM, it fails the same way on this branch and on main (0b01d21), so it is not this wave's; it passes without `-race`.

The first `make check` stopped at the licence check, because the VM's `node_modules` predated QG1's `package-lock.json`; the gate now runs `npm ci` first. The second found what the targeted tests had not: the mail of notifications reads the same rows as the list and still had the old placeholder (fixed by making `visibleRows` name its placeholder), the CHECK on `api_tokens` read the whole table under its lock (now `NOT VALID`), and a test that read the rule string of a route did not expect the scope at its end (fixed).
