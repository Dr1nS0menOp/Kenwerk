# Wave PS1: pasting HTML, held by tests

Pasting is the widest door into the editors: any program can put any HTML on the clipboard. This wave measures how a paste travels, fixes a code-scanning finding in the handling of Word's lists, and adds tests that hold every layer a paste passes.

## How a paste travels

ProseMirror reads pasted HTML in `parseFromClipboard` (`prosemirror-view` 1.42.9, `clipboard.ts`). It calls the editor's `transformPastedHTML`, then parses the string into a detached document made by `document.implementation.createHTMLDocument`, through the Trusted Types policy `ProseMirrorClipboard`, the one policy name the Content Security Policy allows. The editor's schema then reads that document with its parse rules (`clipboardParser`, or the schema's own parser) and keeps only the nodes, marks and attributes those rules read. Drops take the same path.

Measured in Chromium under Kenwerk's policy: the browser checks an inline event handler against the policy as soon as its parser reads one, in a `createHTMLDocument` document, a `DOMParser` document and a `<template>` alike, and reports it as `script-src-attr`. A paste of HTML with handlers therefore yields that report while ProseMirror parses it in the detached document. The handler never runs and never reaches the page: the policy blocks it, the detached document is never shown, and the schema has no rule that reads it. The end-to-end tests below hold all three.

A layer of our own in front of ProseMirror was weighed and left out. A sanitiser that parses with the browser, such as DOMPurify, raises the same report. One that parses without a DOM was found unmaintained, with recent bypass advisories, and would have been a new dependency.

## Word's lists

`cleanWordHtml` turned Word's list paragraphs into lists on the HTML string, and decided between bulleted and numbered by removing the marker's tags with a regular expression and looking for a digit. Code scanning flagged that removal (`js/incomplete-multi-character-sanitization`); it carried a suppression comment.

The lists are now made in the detached document ProseMirror already parsed the paste into (`word-lists.ts`): a parser that extends the schema's own finds runs of `MsoListParagraph` paragraphs, reads the marker between Word's conditional comments by its `textContent`, and builds `ul` or `ol` with DOM calls before the schema reads the document. The regular expressions and the suppression are gone. Word writes its marker comments in two spellings, `<![if !supportLists]>` and `<!--[if !supportLists]-->`; the HTML parser makes both the same comment, so both are now recognised, where the string version knew one. The Google Docs wrapper is still taken off the string (`cleanGoogleDocsHtml`).

Unit tests run without a browser, so the two unit tests of Word's lists became end-to-end tests.

## The schema as the allow-list

`paste-schema.test.ts` hands every parse rule of the page editor's schema and of the header and footer's an element whose every attribute, under every name a rule may read it by, holds `javascript:alert(1)`, with event handlers and a style of `expression(...)` and `url(javascript:...)`; style rules get those values too. It holds that no rule keeps an attribute named `on…`, an address attribute that `isSafeAddress` refuses, or a style expression.

It found two address attributes that the schema read without a check: the link of an image (`href`) and the address of a spotlight's button (`button_href`). Both now pass `safeAddressOrNull`, the editor's existing rule for addresses (`shared-clean.ts`), when they are read. Links already passed TipTap's `isAllowedUri`, and the header and footer's own rule.

It also showed that the attributes of dynamic blocks that hold JSON throw on text that is not JSON, which fails a paste as a whole; the test retries such a rule with the hostile address written as JSON.

## End-to-end tests

`expectHostilePasteHarmless` (`e2e/helpers.ts`) pastes HTML with an image error handler, a mouse handler, a script and a `javascript:` link, as raw HTML on the clipboard, into the focused editor. A `MutationObserver` and a listener for policy reports are installed before the paste. It holds that:

- nothing with an `on…` attribute, no `<script>` and no `javascript:` address is ever attached to the page;
- the only reports are `script-src-attr`, the policy blocking the handlers in the detached document, and there is at least one;
- no handler ran (a handler would set a mark on the window), no script error happened and no dialog opened.

It runs in the page editor and the comment box (`blocks.spec.ts`) and in the header field (`header-footer.spec.ts`), each of which then holds that its content has no script, handler or `javascript:` link. `blocks.spec.ts` also pastes Word lists: a bulleted run in both comment spellings with a font size in its markup, a numbered run after an ordinary paragraph, and a list numbered with letters.

## Mutations

Four mutation lines in `scripts/mutation-check.sh` take away each check of an address read from HTML: the image link, the spotlight button, `safeAddressOrNull` itself, and the header and footer's link rule. `paste-schema.test.ts` catches all four.
