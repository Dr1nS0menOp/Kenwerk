# Report: wave ST1, the identity provider, the helpers, the metrics token and the name in the administration (spec 101)

## What was asked

The product owner's rule is that Kenwerk is a GUI and API first product: what today comes only from environment variables must also be set in the administration and through the API. Wave ML1 did this for the mail server (spec 098). This wave does the same, with the same pattern, for the identity provider (`KENWERK_OIDC_*`), the PDF helper (`KENWERK_PDF_*`), the office service (`KENWERK_COLLABORA_URL`), the drawing service (`KENWERK_DRAWING_URL`), the metrics token (`KENWERK_METRICS_TOKEN`) and the instance name (`KENWERK_INSTANCE_NAME`), and says what stays in the environment and why.

## Through the API

Spec 101 lists the routes and their scopes. A token with the `admin` scope reads the connections, never a secret; changing them is a session's, as for all of the administration (spec 085, spec 096 D5).

## What stays in the environment

Spec 101 lists it with its reasons: settings read before the database or the console exists (role, listen address, public address, database and queue addresses, folders, the master key, migration and shutdown settings, session ceilings, tracing), the fence around what the console may reach (`OUTWARD_ALLOW_PRIVATE`, trusted proxies), and secrets another process reads from its own environment (`COLLAB_URL`, `COLLAB_TOKEN`). The log level and the backup schedule already had their place in the console.

## Decided on the product owner's behalf (may be overruled)

D1 to D11 in the spec. In short: one module and one row for the five connections, the name stays in Look; the environment wins per unit (the provider as a whole, each helper on its own); every change is guarded, the drawing service too; what the server reaches goes through `internal/outward`; secrets sealed and never returned, the metrics token made in the browser; no test button in this wave; four places keep the start name; one audit action; the parts join Login and General so the sidebar does not move; the read is `admin:read`; a limit is checked after the code, the lock before it.

## What was not proven

- A real identity provider over https on a public address: the tests use a fake provider on this machine, reached with `KENWERK_OUTWARD_ALLOW_PRIVATE` on.
- Two nodes in separate processes: the tests run a second app on the same database in one process.
- A real Gotenberg, Collabora or draw.io set from the administration: the tests check the address in force, the policy header and the refusal of an inside address.
