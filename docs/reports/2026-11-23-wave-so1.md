## 2. Start of the wave

The branch `wave-so1` held only the plan (spec 088, 2026-11-16), on a base from before wave SC4. The build started on a new branch from `main` (e5e8323), with the plan brought over and rewritten as built: SC4's registry, `SettingsSection` and every section a step links to now exist, and two things decided since were taken in: every feature is reachable through the API and so through MCP (2026-11-17), and the overview also covers tokens, public sharing and the key that seals secrets.

## 3. What was built

- **`internal/hardening`** (new, pure): `Facts`, `Evaluate`, `AttentionCount`, the thresholds, and `Cache`, which keeps one answer per node for 30 seconds.
- **The facts** (`internal/app/security_overview.go`), each through its owner's Go API, so the module boundary list did not change: `identity.SecurityCounts` (one statement over active accounts, their credentials and the tokens that still work), `sites.LiveEverywhere`, `instance.CreatedAt`, `db.CurrentRole` (the catalogue), `scim.Tokens`, `exchange.Limits`, `backups.Overview`, `audit.List` for the newest `export.policy_changed`, `keys.promoted` and the worker's `audit.verified`, and the cached health facts. `health.backupWarnAfter` became `health.BackupDueWithin`.
- **The route** `GET /api/v1/admin/security-overview` (`handlers_security.go`): `permission:administrator`, scope `admin:read`, tokens allowed, behind the part. `App.SecurityOverview` checks administration itself too. `withSecuritySteps` adds `security_steps` to the attention list while the part is on, and reads nothing while it is off.
- **Web**: `SecurityOverviewTab`, the pure model `security-overview-model.ts`, the row `SecurityStep`, `IconOpenCircle`, styles, the registry entry, the capability, the summary link, 103 words.

## 4. Leak and safety paths and their tests

| Path | Test |
|---|---|
| A member, a guest, a member's token or no login reads the overview | `TestOnlyAnAdministratorSeesTheSecurityOverview` |
| Code other than the route reaches the answer without the check | the same, calling `App.SecurityOverview` as a member |
| The answer names a person, an address, an id or a token | `TestTheSecurityOverviewNamesNobody` |
| The part is off and the route answers anyway, or the summary counts it | `TestTheSecurityOverviewIsOffOnANewInstallation`, `TestTheSummaryCountsTheStepsThatNeedAttention` |
| Something of the overview is read while the part is off | `TestNothingOfTheOverviewIsReadWhileItIsOff` |
