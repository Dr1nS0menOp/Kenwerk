# Wave QG1: stronger quality gates, held by a ratchet

Builder report. Spec 097 holds the decisions and the plan for QG2 and later; this note holds what was tried and measured.

## Tools and pins

- golangci-lint 2.15.0 (published 16 October 2026, GPL-3.0), gitleaks 8.30.1 (21 March 2026, MIT), Stryker 10.1.1 with its vitest runner (23 October 2026, Apache-2.0). Each version was at least two weeks old.
- The Go tools run as `go run module@version`, as staticcheck and govulncheck already did. Building golangci-lint with our own toolchain also avoids its warning about a Go version newer than the one it was built with.
- `npm install` of Stryker first failed: one of its packages, `@inquirer/ansi` 2.1.1, had been published three minutes before and its tarball was not downloadable yet. `npm install --before=2026-11-07` resolved every package to a version at least two weeks old. Worth repeating for any new package: a release of today is also how a hijacked version reaches people first.

## gitleaks

- History: 371 commits (all branches, merges skipped by gitleaks) in 5.3 s; 7 findings in 3 places. Tree: 3 findings, the same places. All are test values; see spec 097 for the table. No real secret anywhere.
- The first history run with the allowlists still found 3: the message id of the Standard Webhooks test vector, beside its key, in three commits. Its value joined the same allowlist entry.
- `gitleaks dir` does not read `.gitignore`. Without path allowlists it read 196 MB (mostly `node_modules`) in 72 s; with them 25.7 MB in 8 s.
- The canary in `scripts/secret-scan.sh` was checked both ways: with the planted token the scan goes on; with the token replaced by plain text the script stops with "a planted token was not found".

## npm audit

Not applied: it adds a package, and moderate is below the gate; left to Renovate and the product owner.

## golangci-lint

- The first run reported 796 findings; golangci-lint keeps one finding per line by default, so a function both long and complex showed once. With `uniq-by-line: false`: 1,169.
- dupl at 150 tokens has no finding; the standalone `dupl` agrees ("0 clone groups"). At 50 tokens there are many (32 in `internal/pages` alone); 150 is the default and was kept.
- Time: about 37 s to build the tool cold, then 60 s for the analysis cold and 18 s warm, on the development container.
- Exit status: with `go run`, any non-zero status of the tool becomes 1, so "found issues" and "crashed" cannot be told apart. `--issues-exit-code=0` makes the tool exit 0 with findings, so a non-zero status is a real failure; the ratchet then judges the JSON.

## Cleaning

Fourteen packages are clean after this wave (spec 097 names them). Every change splits a function along steps it already had; no behaviour changed. Their package tests and the race run of `make check` pass; the mutation lines on these files were read one by one, and one line (`internal/jobs`, "jobs run during maintenance") was moved to the code's new place. Tried and left for QG2: `mail`, `outbox`, `queue`, `sso` and `webui`, which touch SMTP, the outbox relay, NATS start-up, login and the frontend server, and want more care than a quick split.

## Stryker

- The first run failed in its dry run: `template-conditions.test.ts` and `template-fields.test.ts` read the Go side's tables (`internal/.../testdata/cases.json`, and two Go files) by a path relative to `web/src`, and Stryker runs the tests in a copy of `web/` under `.stryker-tmp`. Fixed with `web/src/shared-cases.ts`, which takes the repository from `KENWERK_REPO` when set (`make mutation-web` sets it) and from the old relative path otherwise. `inPlace: true` was considered and not taken: an interrupted run would leave mutated source behind.
- Second run: 3,680 mutants in 16 files, 722 tests, initial run 22 s; 37 min 33 s with two test processes, under `nice -n 19` beside other builders' gates. Score 71.77% (2,619 killed, 22 timeout, 754 survived, 285 no coverage). Per file in spec 097.
- 687 mutants are static and take 95% of the time; `ignoreStatic` was not used, because it removes them from the score.
- The ratchet's scores, rounded down to a tenth, match Stryker's own table exactly (for example 71.29% covered and 60.00% total for `table-rules.ts`, floor 60.0).

## Gates run

- `make check` in the development container: green, including the new `lint`, `secrets` and `audit`.
- `make mutation` with the changed files: it ran every mutation, because `scripts/mutation-check.sh` itself changed; all 1,407 were caught, among them the moved "jobs run during maintenance" and every mutation of the files split in this wave.

## Not proven here

- The CI jobs themselves did not run: nothing was pushed. `make check` ran in the development container; the history scan ran on a mirror clone of a bundle, as the worktree's `.git` cannot be read inside the container.
