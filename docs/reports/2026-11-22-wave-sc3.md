## Through the API

Every route the editor uses is listed in spec 082, "Through the API". One was missing: a description of the document format, which a script or agent needs to write what the editor writes. `GET /api/v1/document/format` (signed in, or a token with `read`) answers the schema version, the limits, every node with the nodes it may hold, and every mark, built from the same lists the gate checks against (`document.Format`), so it can never describe more than the gate accepts. Tests: `internal/document/format_test.go` (the description matches the gate, and a caller cannot change it) and `TestTheDocumentFormatIsReadableThroughTheAPI` (a stranger gets 401, a session and a read token get the format). Mutation line: "the document format is open to strangers".

## Load budget

Measured as spec 030 did: a page of 1,000 paragraphs and 100,000 words in headless Chromium through the e2e harness, three rounds per run, two runs each of `main` and of this wave, back to back on the same machine, which two other builders were using at the time. The throwaway test was not kept.

| | `main` (3ead067) | This wave |
|---|---|---|
| Open the editor until the last paragraph shows | 493 to 716 ms | 490 to 630 ms |
| Type 38 characters at the end | 13.2 to 16.2 ms a key | 14.0 to 16.1 ms a key |
| Insert, until the dialog's search shows | 194 to 209 ms | 155 to 189 ms |
| The insert dialog with every entry, measured inside the page | | 33 to 76 ms |

The absolute budget of spec 082 (12 ms a key, 600 ms, 100 ms) was set on an idle machine, and `main` misses it on this loaded one as well; the wave is no slower than `main` in any step and faster in opening Insert (D37). A measurement on an idle machine is still owed.
