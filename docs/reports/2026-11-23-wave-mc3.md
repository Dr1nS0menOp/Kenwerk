# Wave MC3: the tools for assistants, and `kenwerk mcp` over stdio

Builder report for the second build wave of spec 096 (access through the Model Context Protocol).

## What was looked at

- Spec 096 in full, the report and handoff of wave MC2, the router and its scope table (`internal/httpapi/router.go`, `scopes.go`, `credentials.go`), `kenwerk client` (`cmd/kenwerk/client.go`), the document format's Markdown reader and writer (`internal/document`), and the handlers behind every route a task tool calls, for their inputs and answers.
- The official MCP Go SDK, `github.com/modelcontextprotocol/go-sdk`, v1.8.0: its licence (existing code MIT, new contributions Apache-2.0; both allowed), the revisions it speaks (2026-07-28 and older, as spec 096 D13 asks), and the modules it brings (listed in `docs/dependencies.md`).

## What changed

- **`internal/mcp`.** The catalogue as data: each tool names its routes, their scopes and its arguments; its input schema is built from the arguments and checked with the SDK's JSON Schema module before anything is sent. One generic runner serves tools that are one request of one route; pages, versions and comments have small runners that turn documents into Markdown and back with `internal/document`. `describe_api` reads the server's `openapi.json`; `call_api` checks the path (clean, below `/api/v1/`, no query or escapes), classifies it against the never list and the approval class with the router's own pattern rules, and sends it only when it is neither.
- **`kenwerk mcp`.** Reads `KENWERK_URL` and the token as `kenwerk client` does, asks `GET /api/v1/me/credential` what the token holds, refuses a token that is not for an assistant, and serves the tools that token can use over standard input and output. It follows no redirect, so the token never reaches another address.
- **`GET /api/v1/me/credential`** and **`scope:any`**: every token reaches the route; the router refuses `scope:any` on any route not in `selfRoutes`. The walk over the route table of MC2 checks that every token reaches it.
- **Docs.** `docs/operations/mcp.md` (connecting Claude Desktop, Claude Code and other clients over stdio; what an assistant gets, does not do, and how pages can try to steer it), `docs/api/README.md`, spec 096 "Built in wave MC3" with D21 to D26, the blueprint status line of PLT-047, `docs/dependencies.md`, the changelog.

## How the tests prove it

See the gate results below. The tests, written before the code they hold:

- `internal/mcp`: a page comes as Markdown marked as data; every result with content starts with the notice; no result holds a secret field or a Kenwerk secret; a refusal of the API comes back in its own words; arguments that do not fit are refused before anything is sent; `call_api` sends nothing of the never list, the approval class, the Administration, a path that is not clean, or outside the API; a read-only connection is offered only read tools and its `call_api` only reads; tools that delete say they are destructive; the list of tools does not change with what the server answers; `update_page` starts from the version given; the caller follows no redirect; Markdown comes in parts that add up and round-trips with its files.
- `internal/app`, against the real router and database: the catalogue follows the route table (every tool's routes exist, its scopes are exactly theirs, its annotations follow them, every route of `scope:none` is on the never list and every listed pattern is a route); a token that only reads, offered every tool, is refused by the API on every tool that changes something, and finds nothing outside its space; every request of a tool is one of its routes; `call_api` sends nothing for any of the routes it must refuse; an assistant writes pages through the tools, a stale version is a conflict, and the audit names its token; the credential route tells a token what it holds and no more; the latency of a tool call against its API call.
- `cmd/kenwerk`: `kenwerk mcp` refuses a token not for an assistant, needs its address and token, and serves its tools over a pipe until the client closes it.
