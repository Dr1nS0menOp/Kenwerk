# Wave OD1: the OpenDocument export opens in LibreOffice

Wave GB1 found that LibreOffice refused Kenwerk's own `.odt` export, on Gotenberg 8.40.0 ("uno exception") and 9.9.3 ("loadComponentFromURL returned an empty reference"), while the Word export of the same pages opened. This wave found why, fixed it, and keeps it checked.

## The cause

The first entry of an OpenDocument package, `mimetype`, tells a reader what the file is. The writer made it with `zip.Writer.CreateHeader` and `zip.Store`. Go's zip writer then sets bit 3 of the entry's flags and writes the size and checksum in a data descriptor after the bytes, for every entry it makes this way. LibreOffice's package reader (`ZipPackage::checkZipEntriesWithDD`) refuses a stored entry with a data descriptor that is not encrypted ("entry STORED with data descriptor but not encrypted"), so it never got to the content. The Word export makes every entry compressed, which LibreOffice accepts with a data descriptor, so it opened.

Measured with the real helper (the image of `deploy/pdf`, Gotenberg 9.9.3): the same package, entry for entry, opens when the `mimetype` entry has its sizes in its header (200, a PDF) and is refused when it has a data descriptor (400, "LibreOffice could not read the document", "loadComponentFromURL returned an empty reference" in the helper's log, the message GB1 saw).

## The fix

- `internal/office/odt.go` writes the `mimetype` entry with `zip.Writer.CreateRaw`, with its checksum and sizes in its local header, no data descriptor and no extra field, as ODF 1.3 part 2, section 3.3 asks.
- The file claims OpenDocument 1.3 (`office:version` in `content.xml`, `manifest:version` in the manifest), and the manifest's entry for the package itself carries the version, as ODF 1.2 and later expect.
- The schema check found three more faults that LibreOffice forgave, which are fixed too: a panel, columns or a table inside a list item was written as a table there, where a list item may hold only paragraphs, headings and lists (they are now written as their blocks one after another inside a list); columns without a column wrote a table with zero columns; and a table without cells, or a row without cells, wrote a table or row with nothing in it (now left out; a caption stays).

## How it is checked

- `internal/office/odt_test.go` writes one page that holds every block and mark the exporters know (headings 1 to 6 and empty, every mark, links outside and inside, a hard break, status, date, mention, page link, template field, alignments, nested bullet, numbered and task lists, a code block, a table, a panel and a quote inside a list item, a list inside a table cell, a quote with a list, a horizontal rule, an image with caption and one that is gone, a file, panels, an expand, columns, a decision, tables with header, column span, background, caption above and below, empty rows and no rows, a chart, an excerpt and an unknown block), three times at different depths, and checks:
  - the package rules: `mimetype` first, stored, no extra field, no data descriptor, its bytes at offset 38; every file in the manifest and every manifest entry in the package; the root entry with media type and version;
  - `content.xml`: the office namespace and `office:version` 1.3;
  - `content.xml` against `OpenDocument-v1.3-schema.rng` and the manifest against `OpenDocument-v1.3-manifest-schema.rng`, the OASIS schemas, with `xmllint --relaxng`. The schemas are in `internal/office/testdata/odf` with OASIS's notice, which allows copies that keep it. The test skips without `xmllint`, except in CI, where it fails; the development toolbox and CI's `go` job now install `libxml2-utils`;
  - with `KENWERK_TEST_PDF_URL` set, LibreOffice in the real helper makes a PDF of that file (`TestLibreOfficeOpensTheODTOfEveryBlock`).
- `TestTheRealPDFHelperMakesAnExportAndOpensOfficeFiles` previews Kenwerk's ODT export of a branch through the app again, beside the Word and RTF files. CI's container job runs both live tests.
- Seven new mutations: the `mimetype` entry with a data descriptor, compressed, or not first; a picture missing from the manifest; the package entry without its version; the content claiming 1.2; a table inside a list item.

With only the `mimetype` and version fixes in place, the schema test failed on the tables in list items and the empty grids, while LibreOffice already opened the file; with the whole fix every test passes. The mutations show that each package test fails on the old way of writing.

## Not proven

- Only LibreOffice in Gotenberg 9.9.3 was tried; Microsoft Word and other readers of OpenDocument were not.
- The schema check covers `content.xml` and the manifest. The package has no `styles.xml` or `meta.xml`, which OpenDocument does not require.
