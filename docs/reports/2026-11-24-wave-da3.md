# Wave DA3: the dependency decisions of 2026-11-24

Written for: the product owner and later build sessions. This wave carries out the four decisions recorded in [the dependency review of 2026-11-24](2026-11-24-dependency-review.md).

## 1. TOTP: `pquerna/otp` replaced by `creachadair/otp`

- `creachadair/otp` 0.5.6 (BSD-3), root package only. Its `otpauth` package is not imported, so `creachadair/wirepb`, which has no release, is not compiled in. Its `go.mod` still names wirepb, `mds` and the staticcheck tool, so they join the module graph (`go.sum` gains `mds`), but `go list -deps ./cmd/kenwerk` holds no module of creachadair's other than `otp` (checked on the build VM).
- The code is in `internal/identity/totp.go`: a seed of 20 random bytes in unpadded base32 (the shape `pquerna/otp` made), the `otpauth://` address written exactly as before, and the QR code drawn with `boombuler/barcode`, now a direct dependency. `matchTOTP` in `factors.go` keeps its rules: the step now and one either side, a constant-time comparison, and the step returned so that `useTOTP` refuses a code whose step is not newer than the last one used (`last_step`, unchanged).
- One small difference, on purpose: the issuer in the query is escaped as a query value, so a name with `&` or `=` no longer breaks the address. A space is still `%20`, as some apps need.
- Existing seeds keep working with no re-enrolment: the new library decodes the stored base32 the same way (upper case, optional padding, spaces ignored).

Tests, written before the code: the six SHA-1 vectors of RFC 6238 appendix B (cut to six digits), checked against a reference of RFC 4226 written out in the test; one step either side accepted under its own step, two steps refused; spaces and lower case; a broken seed is an error; 160-bit seeds that differ; the exact enrolment address; the QR code compared pixel by pixel with the code of the address; and, in `internal/app`, an authenticator sealed as the old library wrote it logs in and its code is refused a second time.

Mutations: every TOTP line kept (the replay mutation now also runs the upgrade test), and seven new: a two-step window, no step before, the wrong step returned, eight digits, an 80-bit seed, the period dropped from the address, and a QR code of another address.

## 2. `y-indexeddb` removed

- `web/src/components/editor/together.tsx` no longer keeps the shared document in IndexedDB; the editor waits for the service's first sync. Offline typing stays in the open tab and merges when the connection returns (COL-091, `typing offline merges on return` in `collab.spec.ts`). The offline strip now says to keep the page open.
- `web/src/personal.ts`: the marks of unsaved shared typing and the clean-up at logout and at start are gone. In their place, `dropOldSharedCopies`, called once when the app loads (`main.tsx`), deletes every IndexedDB database named `kenwerk.person.<id>.shared.<page>`, of anyone, and the `kenwerk.person.<id>.unsaved.shared.<page>` marks in `localStorage`. Page text that failed to save (PAG-016) is untouched.
- Tests: `personal.test.ts` (which names are found, and that loading deletes the copies and marks but keeps unsaved page text); the e2e test in `collab.spec.ts` that replaced "offline text leaves at logout" makes an old copy, reloads, sees it gone, edits a page and finds no IndexedDB database at all. The mutation "offline text stays after logout" lost its code and became two: an old copy stays, and the old marks stay.
- Lost on upgrade: typing done offline with an earlier version that never reached the service, and sat only in that browser's copy. The CHANGELOG says so.
