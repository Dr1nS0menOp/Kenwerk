# Dependency review, 2026-11-24 (wave DA2)

Written for: the product owner, who decides on replacements and exceptions, and later build sessions, which act on the verdicts. Documentation only: no code, dependency or configuration changed in this wave.

Every security-critical and architecture-critical dependency of Kenwerk, reviewed together in one run, each with its OpenSSF Scorecard and the best alternative found. The complete list of dependencies, critical or not, is [the dependency inventory](../dependency-inventory.md): 582 rows, 130 of them critical, generated by `scripts/dependency-inventory.mjs`.

## How dependencies are judged

The product owner's rule of 2026-11-24: every judgement of a dependency includes its OpenSSF Scorecard and a real search for something better: other maintainers, maintained forks that carry a project on, big vendors (Google, Cloudflare, Microsoft, AWS, HashiCorp and others), and the standard library. All security-critical and architecture-critical dependencies are reviewed together, and the complete list of dependencies is kept in view ([the inventory](../dependency-inventory.md)).

The base rule for security dependencies, from the product owner on 2026-11-23, applies to all of them:

1. a release in the last 12 months and commits in the last 6; not archived;
2. past advisories fixed within about 30 days, none open;
3. an organisation, or at least two active maintainers;
4. widely used, with a Scorecard;
5. a licence on the allow-list in `scripts/check-licenses.mjs`; exceptions only by the product owner, recorded with a reason;
6. as few modules as possible; never hand-roll crypto or protocols.

Switching an architecture-critical dependency costs a lot, so a switch is recommended only when the gain is clear.

The verdicts:

- **keep**: passes the rule, and no alternative found is clearly better.
- **watch**: passes the rule but for one weak point in rule 3 or 4 (one active maintainer, or no Scorecard), or is held in place by a parent Kenwerk keeps. Re-checked every quarter.
- **replace**: fails the rule, or something clearly better exists, and Kenwerk can act.
- **exception**: fails the rule, and the product owner keeps it on purpose, with a reason and a date to look again.

## What counts as critical

- **Security-critical**: logins, sessions and tokens (OIDC, OAuth, JOSE, JWT, WebAuthn, TOTP), cryptography and passwords, parsers of untrusted input (HTML, Markdown, YAML, CBOR, JSON from assistants), the database driver, the queue, the MCP SDK, the editor and collaboration code that handles user content, the runtime images, and the CI actions and tools that see secrets or sign a release.
- **Architecture-critical**: hard to replace once built in: the database driver, the queue, the editor framework (Tiptap and ProseMirror), collaboration (Yjs and Hocuspocus), React, the data-fetching library, i18next, the build tools of release artifacts (Vite and its bundler Rolldown, GoReleaser), the OpenTelemetry SDK, the MCP SDK, the OAuth library, `google/uuid` (used in 246 files), and the base images.

Kenwerk has no router library (its own `httpapi.Router` over `net/http`), no SAML or SCIM library, no sanitiser (documents are rebuilt from an allow-list), and no client-side router package: `web/package.json` does not contain `@tanstack/react-router`. HTTP servers and clients, TLS, ZIP, images and mail come from the Go standard library.

## The four decisions of 2026-11-24

| Decision | Reason | What follows |
|---|---|---|
| `google/uuid` stays, with an exception | It fails rule 1 (no release since 2024-01), but it is Google's, has never had an advisory, and Go 1.27's standard `uuid` lacks the name-based v5 that Kenwerk uses at five places, which must not be hand-rolled | Look again at every Go release: once the standard library has v5, or Kenwerk no longer needs it, move to the standard package |
| TOTP moves from `pquerna/otp` to `creachadair/otp` | pquerna/otp fails rules 1 and 3 (no commit since 2025-08, nobody active). creachadair/otp is released (2026-11-08), BSD-3-Clause, and its root package needs only the standard library | It has one maintainer and about 20 stars, so it fails rule 3 and is weak on rule 4: it is on **watch**, and the decision is in effect an exception to those two rules, to be written down as one. Recommended: use only the root package, because the `otpauth` package would bring `creachadair/wirepb`, which has no release; the `otpauth://` address for the QR code is then a few lines of URL building, with no cryptography in it. The build wave weighs this against taking `otpauth` with wirepb. `boombuler/barcode` becomes a direct dependency for the QR code |
| `y-indexeddb` is removed | It fails rule 1 (last release 2023-11), and the offline copy is not needed; removing it also stops page content lingering in browsers on shared machines | One module fewer |
| `lowlight` stays, with an exception, re-checked quarterly | It fails rules 1 and 3, but has never had an advisory, emits a syntax tree rather than HTML, and the Tiptap code-block extension needs it; no drop-in replacement exists | Re-check every quarter; drop highlighting or move if it becomes unsafe |
