# Wave DU1: dependency audit wave 1, the low-risk updates (2026-11-23)

The product owner's rule of 2026-11-23: dependencies that matter for security are kept maintained and patched quickly, and updates land promptly. A dependency audit (DA1) went through every module, package, image, action and release tool against six criteria and split the work into waves. This is wave 1: updates inside the current major versions, which change no behaviour on purpose. Majors, new base distributions, the Go 1.27 toolchain and the four packages the audit says to replace wait for later waves and for decisions.

Nothing else in the lock moved apart from what these packages bring: minimatch 11.0.9 for ESLint, with its new helper `@isaacs/nonrecursive-glob-match` (BlueOak-1.0.0, development only, allowed for tools by the licence check).

**highlight.js.** There were two copies: 11.11.2 under `lowlight`, which is the one the editor uses, and 11.12.0 at the top, installed only as the peer that `@tiptap/extension-code-block-lowlight` names and imported by nothing. lowlight 3.3.0, its newest release, asks for `~11.11.0`. 11.12.0 bounds the C and C++ type tokens and drops recursive sub-language references in XML, both to stop very long runs on crafted text (its changelog calls them ReDoS fixes). So `web/package.json` now has `"overrides": { "highlight.js": "11.12.0" }`, and the tree holds one copy, 11.12.0. lowlight uses only `highlight.js/lib/core` and the grammar modules, whose interface did not change in this minor release; the unit tests of `code.ts` and the design pictures with code blocks are the check.

**prosemirror-view held at 1.42.9.** With 1.43.1, `file-details.spec.ts` "a tile can be large, and that stays after publishing" failed twice in a row on the build VM: after a click on a file tile the File tile control never appeared, so the click no longer made a node selection of the tile. 1.43.0 (2026-11-19) says mouse selection is now handled by the library rather than the browser. With `"prosemirror-view": "1.42.9"` in `overrides` and nothing else changed, the whole spec passed. Tiptap 3.35.0 asks for `^1.42.6`, so the hold is inside its range. 1.42.9 was released 2026-10-31 and is after the fix of the last advisory (1.42.3). Whether our file node view needs a change for 1.43 or 1.43 has a bug was not looked into; the next wave that moves ProseMirror should try the newest release against this test first.

## Renovate

`renovate.json` exists, and the question was whether Renovate runs at all. It does. From the public GitHub API on 2026-11-23:

- Renovate (the hosted Mend app) opened its Dependency Dashboard, issue 2, on 2026-11-21 at 13:09 UTC and last updated it on 2026-11-23 at 11:40.
- It opened 29 pull requests on 2026-11-21 between 22:13 and 22:18 UTC, and has rebased several since, the last on 2026-11-23. All 29 are open; none was merged or closed. Among them are the three digest refreshes this wave made (golang, node, postgres), the grouped Go update, the GitHub Actions update, Tiptap, Hocuspocus, i18next and react-i18next, and majors such as Go 1.27, Node 26, Gotenberg 9 and PostgreSQL 19.
- The checks run on its pull requests and mostly pass, but the `dco` job fails on every one: Renovate's commits carry no `Signed-off-by` line.
- Waves land on `main` by direct push, and nobody merges pull requests, so even a green Renovate pull request would wait forever. That is why the digests were about two weeks behind: Renovate found them, and nothing took them in.
- The dashboard lists two updates held back by Renovate's rate limit.

Wave DU1 took over the safe content of these pull requests by hand. It did not change any repository setting. What should happen to Renovate's pull requests is for the product owner (see the handoff).

## Not in this wave, and why

- Majors: i18next 27, react-i18next 18, Gotenberg 9, TypeScript 7: they need testing and decisions.
- Debian 13 and Node 26 base images, distroless static-debian13, the Go 1.27 toolchain: wave 2.
- The four packages the audit says to replace (`google/uuid` after Go 1.27, `pquerna/otp`, `y-indexeddb`, `lowlight`): decisions for the product owner.
- `go-webauthn/x` 0.4.1: only when `go-webauthn/webauthn` asks for it.
- The dependencies of Stryker: `overrides` entries for a development tool, planned with the audit's later items.
- Dev-only images without a digest in `compose.dev.yaml` and `Dockerfile.dev`, and the other development tools (vite, vitest, Playwright, prettier): not security-relevant by the audit's brief.

## Not proven

- That 11.12.0 changes no colouring Kenwerk shows: only the code blocks in the design pictures and the unit tests look at it.
- How Renovate's `vulnerabilityAlerts` behaves: it needs GitHub's Dependabot alerts on the repository, a setting this wave cannot read.
