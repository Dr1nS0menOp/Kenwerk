# Wave SV1: addresses of image links and spotlight buttons

Addresses of image links and spotlight buttons are now checked on every save and when rendered.

## Tests

- `internal/document/block_addresses_test.go`: the document gate, the HTML writer of exports, PDF files and published sites, and the Markdown export, with sixteen addresses on an image link and a spotlight button: `javascript:` in mixed case, with space, tab, newline, a no-break space or a control character before it, with a tab or a NUL inside the scheme, `data:` as text and as base64, `vbscript:`, and the colon or the first letter written as an entity or escaped.
- `internal/app/block_addresses_test.go`: the same addresses through publish, draft, a new space, a template, a template file, a saved block, an imported web page and a bundle. Each is refused with the reason "links must use http, https or mailto, or be a relative path", and nothing of it is stored; the same blocks with an ordinary address are kept.
- `web/e2e/blocks.spec.ts`: the same through publishing in the browser's session, and the reading view, which shows the picture and the words with no link for such an address, and both links for safe ones.

## Stored data

No worker pass and no migration was needed; the check when rendered covers any stored value.
